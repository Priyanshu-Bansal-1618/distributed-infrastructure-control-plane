# ADR-003: Versioned Snapshots for Data Plane Isolation

## Status
Accepted

## Context
In microservice architectures, request latency in the data plane (load balancer) must remain independent of control plane churn, gossip convergence delays, or registry lookups. Synchronously querying a distributed registry during every HTTP request introduces latency spikes, lock contention, and cascading failures.

## Decision
The Load Balancer consumes **immutable, versioned backend snapshots** generated by the control plane:
1. Snapshots are stored as an immutable data structure wrapped in `std::shared_ptr<const BackendSnapshot>`.
2. Reader threads (proxying client requests) acquire the current pointer via lock-free `std::atomic_load` / copy.
3. Control plane updates create a brand new snapshot instance and publish it via `std::atomic_store`.
4. In-flight requests continue executing against their acquired snapshot without synchronization contention (Read-Copy-Update semantics).

## Consequences:
- Zero lock contention on the critical request path.
- Strong snapshot isolation for each proxy request.
- Graceful backend draining without stopping incoming requests.
